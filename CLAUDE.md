# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

DDBench: a benchmark of 60 real-world bugs from 13 open-source distributed systems (Go, C++, Java/Scala, Rust, Erlang). Every case is built and run in Docker by `bench.sh`. An agent under evaluation gets the buggy upstream repository plus `SYMPTOM.md` (and, in the context-augmented condition, `context/`), edits the source in place, and is scored by the case's oracle `cases/<case>/reproduce.sh`. There is no host (non-Docker) workflow.

## Repository structure

- `bench.sh` — orchestrator (setup, reproduce, eval, validate-oracle, eval-all, shell, agent, reset, ...). Run `./bench.sh help`.
- `harness/` — agent runner and scoring (`run_agent.sh`, `score_case.sh`, `extract_patch.sh`, `score_surface.sh`, `aggregate_results.py`, `analyze_trajectory.py`, `eval_all.py`) and mini-swe-agent configs in `harness/configs/`.
- `docker/` — Dockerfiles: `base-cpp`, `base-go`, and one per project; base images pinned by digest.
- `addons/` — runtime tool injection for `shell`/`agent` (AI agents, debuggers); `addons/examples/` are shipped, `addons/*.sh` are user overrides (gitignored).
- `.devcontainer/<case>/devcontainer.json` — one per case (60), generated by `scripts/generate_devcontainers.py`.
- `cases/<project>-<issue#>-<slug>/` — the problem (never mounted into agent containers):
  - `case.yaml` — declarative spec: project, repo, buggy_commit, fix_commit, resolve_time, build command, docker caps/num_cpus
  - `reproduce.sh` — the oracle (exit 0 PASS / 1 FAIL / 2 ERROR); runs only inside the bench.sh scoring container
  - `symptom.md` — observable behaviour; copied into the worktree as `SYMPTOM.md`
  - `context/` — optional debug context (observational only), mounted read-only with `--context`
  - `README.md`, `reproduce.md` — human documentation (manual reproduction steps; reproduce.md's "Oracle verdict" section says what PASS/FAIL/ERROR mean)
  - optional oracle harness files (`inject_test.go`, `inject_test/`, `test_main.go`, `test_stall_shutdown.cc`)
- `cases-solution/<case>/` — `solution.md` (root cause + fix) and `gold.patch` (source-only fix the oracle must accept). Never consult during evaluation.
- `registry/` — `case_registry.json` (generated), tier membership and definitions, `resolve_times.json`, `oracle_validation.json`.
- `docs/` — `oracle-validation.md` (soundness of every oracle), `mining/` (historical candidate-mining notes).
- `scripts/` — generators/statistics (`generate_registry.py`, `generate_devcontainers.py`, `benchmark_stats.py`, `context_bundle_stats.py`).
- `mining-protocol/` — how to author new cases (templates, checklist); `.claude/skills/` — Claude Code skills for mining/authoring/verifying cases.
- `index.md` — master list of all 60 cases.

## Working with cases

```bash
./bench.sh setup <case>                 # image + truncated case repo + build + dependency warm-up
./bench.sh reproduce <case>             # oracle on the current worktree → 0 PASS / 1 FAIL / 2 ERROR
./bench.sh shell <case> [--addon <n>]   # human shell: /workspace/src, oracle at /bench/reproduce.sh
./bench.sh agent <case> --addon <n>     # agent container (no /bench, no oracle, no dependency cache)
./bench.sh reset <case>                 # pristine buggy worktree, rebuilt
./bench.sh eval <case> --patch f.diff   # score a patch (JSON with --json)
./bench.sh validate-oracle <case> --runs 3   # buggy must FAIL, gold.patch must PASS
./bench.sh eval-all --predictions p.jsonl --out DIR --jobs 4
```

Key invariants (see the comments in `bench.sh`):

- **Containment:** each case repository contains only the ancestry of the buggy commit (no refs, no remotes, no later objects); setup aborts if this fails.
- **Opaque identity:** every container uses `/workspace/src`; volumes and containers are named `bug-bench-{ws,ctx,deps}-<uid>` / `bug-bench-<uid>` with uid = sha256(case)[:12] and labelled `ddbench.case=<case>`. Nothing an agent sees names the case.
- **Agent isolation:** agent containers never get `/bench`, the host `~/.claude` (only the claude-code addon's credentials/settings), or the case's dependency cache.
- **Offline scoring:** setup fills a per-case dependency cache (`/deps`: Go modules/build cache, Cargo, Gradle, Maven) by building and running the oracle once online; reproduce/rebuild/reset then run with `--network none`.
- **Every reproduce.sh runs the worktree's REBUILD.sh** (owner decision; do not add hardening against it). Oracle tests are injected fresh under `DDBenchOracle*` names and verdicts come from structured test output.

## Commands for this repo itself

No build step. Useful checks:

```bash
bash -n bench.sh harness/*.sh cases/*/reproduce.sh
python3 scripts/generate_registry.py --check
python3 scripts/generate_devcontainers.py --check
```
